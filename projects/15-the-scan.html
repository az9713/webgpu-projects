The scan, and everything it builds

One kernel, CumSum, runs a prefix sum: each output cell holds the running total of every input cell before it. That single idea, plus a comparison and a select, is the whole machine behind four very different jobs below — keeping only the rows that match, finding the runs in a sequence, building a histogram, and handing every item its own slice of a shared output buffer. Nothing here sorts anything; there is no sort kernel in the library.

The science

A prefix sum answers one question for every element at once: how much comes before me? That answer is an address. If each element contributes 1 when it should be kept and 0 when it should be dropped, then the running total before an element is exactly the slot it belongs in once the dropped ones are gone. Nothing needs sorting and nothing needs a queue, because every element computes its own destination without consulting any other.

Four different-looking jobs here are the same three moves. A comparison marks each element, a select turns the mark into a number, and a prefix sum turns those numbers into positions. Keeping matching rows, finding runs in a sequence, building a histogram, and handing every item its own slice of a shared buffer differ only in what is being counted.

Every result is checked against plain JavaScript on the same data. The histogram's 16 bins sum to 4096, which is forced: 4096 samples each land in exactly one bin, so the totals cannot come to anything else. Bin by bin, the card and JavaScript agree. Compaction finds 13 matches against 13, run-length encoding finds 15 runs against 15, and the allocator hands out 57 slots against 57.

One stop is unavoidable. ScatterND requires its indices as 64-bit integers, and no kernel on this card can produce a 64-bit integer, so each scatter reads its positions back to the processor, rounds them, and uploads them again. That is the library's limit, not a choice made for speed.

Every demo runs the same three moves. A comparison (Equal) makes a boolean flag per element. A select (Where) turns that flag into a number, or turns a computed position into a real index versus a harmless dump slot. A prefix sum (CumSum, run exclusive so a cell's value is the count of everything before it, not including itself) turns "is this true" into "where does this go". The one kernel that cannot run this pipeline end-to-end is ScatterND: it wants its indices input as int64, and no kernel on this card can produce int64, so every scatter here takes one deliberate trip through JavaScript — read the float32 positions back, round them, box them as BigInt64Array, upload again. That is not a performance choice; it is the one place the library forces a CPU stop. Range only appears once, to generate the bin numbers 0–15 for the histogram, because that is the only demo that needs a fresh sequence rather than a scan over data that already exists.

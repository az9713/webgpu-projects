Convolution unmasked — im2col, one matrix multiply, and back

Two panels compute the same filtered image. The left panel calls Conv directly. The right panel never calls it: for every output pixel it Gathers the nine pixels under the 3×3 window into one big column matrix, multiplies that matrix by the flattened kernel with a single MatMul, and folds the flat result back into an image with Col2Im. Both panels read the same nine numbers as their filter. Switch the preset and both panels redraw.

The science

A convolution slides a small filter over an image and, at every position, multiplies the overlapping pixels by the filter weights and adds them up. That is a matrix multiply wearing a disguise, and im2col removes the disguise. Every 3×3 window the filter will ever see is copied out as a column of nine numbers, so a 128×128 output becomes a 9×16384 matrix. The filter flattens to a single row of nine. One matrix multiply of that row against that matrix computes every output pixel at once, and the result is folded back into an image.

Both routes run here on the same picture. The left panel calls Conv once. The right panel never calls Conv at all: one Gather with a precomputed index tensor builds the column matrix, one MatMul does every multiply and add, and Col2Im folds the column back into a picture.

The two disagree by at most 1.192e-7 across all 16384 pixels, with a mean of 1.5e-8. That number is not merely small; it is exactly 2−23, one unit in the last place of a float32 near 1.0. The two routes compute the same nine products and differ only in the order they add them, so the smallest representable disagreement is also the largest one that appears. The identity is exact; only the rounding is not.

The cost is memory. Each pixel is copied into nine columns, so the intermediate matrix is nine times the size of the image. That is the trade im2col makes: it buys a single dense matrix multiply, which hardware is very good at, by spending memory it did not previously need.

The source image is padded by one pixel of zeros on every side, once, in JavaScript, so both panels start from the same 130×130 buffer and neither has to special-case the edges. The direct panel is one Conv call with pads: [0,0,0,0] against that padded buffer, kernel_shape 3×3. The im2col panel never touches Conv: a single Gather call reads all nine shifted copies of the padded image at once, using an index tensor of shape [9, 128×128] computed once in JavaScript (index k = i×3+j reads the pixel offset by kernel row i, column j — the same order the flattened kernel uses), producing the full im2col matrix in one shot. One MatMul of the flattened 1×9 kernel against that matrix does every multiply-and-accumulate the convolution needs. Reshape adds back the batch and channel dimensions MatMul does not carry, and Col2Im folds the [1,1,128×128] column back into a [1,1,128,128] image — with a block_shape of [1,1] there is nothing to overlap and sum, so the fold is exact. Sub then Abs compute the per-pixel gap between the two panels on the card; only the final numbers and the two images are read back to JavaScript.

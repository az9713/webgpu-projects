Why the stable form of softmax exists

Two panels compute the same thing. The left one writes softmax the way the definition writes it, exp(x) / Σ exp(x). The right one subtracts the largest input first, which changes nothing in exact arithmetic and everything in float32. Raise the inputs with the slider and watch the left panel fill with non-numbers while the right panel does not move. Every exponential, sum, division and non-number test is a kernel call.

Lights: teal — the value is a number. Amber — IsInf says infinite. Red — IsNaN says not a number. The bars are the probabilities, and the eight of them should always add to 1.

The science

Softmax is unchanged by a shift. Add a constant c to every input and each term of exp(xi) / Σ exp(xj) gains a factor ec top and bottom, which cancels, so softmax(x + c) = softmax(x) exactly. The stable form spends that freedom on c = −max(x): the largest exponent becomes exp(0) = 1, the sum is at least 1, and nothing can grow.

Float32 stops at 3.4028235×1038, so exp(x) goes infinite above ln(3.4028235e38) = 88.72284. This card bisects to 88.7228. But the sum breaks first, at 88.2645, which is that limit minus ln(Σ e−k) for k = 0…7, or 0.45834. The band between the two is the reason this page exists: every exponential is still finite, the sum is infinite, and finite divided by infinity is zero. At a slider value of 88.5 the naive panel returns eight zeros, is off by 0.63, and lights no red — IsNaN has nothing to report. It is wrong in silence. Above 88.7228 it is infinity over infinity, and the red lights come on.

Underflow mirrors it. Every exponential flushes to zero below ln(1.1754944e−38) = −87.3365; measured −87.3366. That confirms independently that this GPU discards subnormals, which page 09 found another way — kept subnormals would break at −103.97.

The stable route never moves: 5.9×10−8 from the reference everywhere between −120 and 120, which is float32 rounding of the reference itself, not error. The Softmax manifest states it subtracts the max internally. The ReduceLogSumExp manifest promises only log(sum(exp(x))), yet it too survives to 120 here, tracking to 2.3×10−6 — undocumented, so not to be relied on.

The eight inputs are the slider value and then that value minus 1, 2, … 7, so the correct answer never changes as the slider moves. The naive route is Exp, ReduceSum over the last axis, Div. The stable route inserts ReduceMax and Sub in front of it. Both divisions broadcast a shape-[1] scalar against a shape-[1,8] row. IsInf tests the exponentials and the sum, IsNaN tests each output, and both answers come from the GPU rather than from JavaScript. The three break points are found by bisection on the card, twenty-eight halvings each, calling the same naive routine that draws the left panel.

What You Can Build With 207 WebGPU Kernels

Eighteen categories. 121 projects, ranked inside each category by visualization, significance and surprise, and scored on seven independent axes with a weighted total. Every one can be built as a single HTML file for this laptop. Compiled 4 September 2026.

This follows the research report. That document explained what the kernels are. This one answers a different question: what can a person actually make. Every kernel name below was copied from the Hub API list of 207. None are invented.

Before the listThe four rules every project obeys

One file, no build step. Each project is a single HTML page, served by python -m http.server. It imports the library from a CDN. There is no npm, no bundler, no server code. A file:// page fails, because the module import is blocked.

Keep the data on the GPU. Pass { output: "gpu" } between steps. Read back once, at the end. On this RTX 3050 that turned a 1024×1024 ai.onnx.MatMul from 26 ms into 9.3 ms. This rule matters more than any other optimisation here.

There is no model runner. You cannot point the library at an .onnx file. Every project that mentions a model is wired operation by operation, by hand. Where a whole model is needed, Transformers.js runs the model and kernels do the extra maths. Those carry a hybrid tag.

No camera. Image projects take a dropped file or a canvas. Audio projects work from a dropped file, and from the microphone as well if you want one.

Four absences to check before you design anything

No random number generator. There is no RandomNormal, no RandomUniform, no Multinomial. The ai.onnx.Dropout manifest is explicit: the package is inference-only, it copies the tensor unchanged, and seeded randomness is not supported. Make noise in JavaScript, upload it once, then re-use it on the GPU.

No sort. ai.onnx.TopK is the only ordering operation in the set. A full sort must happen in JavaScript.

No matrix inverse and no decomposition. There is no Inverse, Solve, QR, SVD or Cholesky. Every linear-algebra project below is therefore iterative. Category 13 is built on that single fact.

The fastest MatMul path is closed on this laptop. Chrome reports subgroup-matrix: false on both of your adapters. shader-f16 and subgroups are true. You get a correct answer on a slower shader variant, not an error.

Plumbing kernels are not repeated. ai.onnx.Reshape, Transpose, Concat, Slice, Pad, Tile, Expand, Squeeze, Unsqueeze, Flatten, Split and Cast appear in nearly every project. Naming them 121 times would add nothing. ms marks a com.microsoft kernel: read its card first, because these expect ONNX Runtime packing conventions.

The ranking uses three axes: visualization, significance and surprise. Each project says which one put it where it is. Some entries say teaching value instead. Treat that as a narrow form of significance: the project is correct and clear, but it explains something rather than doing something new. Those entries always sit at the tail of their category.

RankingAll 121, scored on seven axes

Every project above now carries a score line. This section says what the seven numbers mean, how the total is weighted, and lists all 121 in one sortable table. The scores are one reader's judgement applied consistently across the whole list. They are not a measurement. Nothing here is built, so no score is confirmed by a running page.

The seven axes

Each axis runs from 1 to 5. Each is scored on its own. Two axes are inverted, which means a low number is the good one: cost and risk.

Axis definitions

Visual — how much the screen shows. 1 is a number or a table. 3 is a static plot. 5 is a live picture you can drag, where the picture is the mathematics.

Explain — what a reader understands afterwards that they did not before. 1 is a feature demonstration. 3 makes a known idea concrete. 5 corrects a common wrong belief.

Surprise — how unexpected the result is to a reader who knows the field. 1 is the expected answer. 3 is a known effect, rarely seen. 5 makes an expert check it again.

Kernel — how hard the project pushes the 207-kernel set. 1 is one kernel plus plumbing. 3 is a chain of four to eight kernels, all on the GPU. 5 means one of this document’s documented limits is the project’s main obstacle: a com.microsoft packing rule, the missing sort, the missing inverse, or subgroup-matrix: false. A project that meets a limit and works around it in one line stays at 3 or 4.

Cost (inverted — low is good) — build effort. 1 is Tier A, pure kernels, a few hours. 3 is Tier B, which needs input data or a Transformers.js hybrid. 5 is Tier C, which needs real weights or com.microsoft packing.

Risk (inverted — low is good) — the chance that it does not work, or that it works and is dull. 1 means every dependency is confirmed on this laptop. 3 means one unmeasured assumption. 5 means it depends on something this document lists as absent or unproven.

Standalone — does it hold up outside this catalogue. 1 makes sense only beside its neighbours. 3 is a good page on its own. 5 is a page a stranger would keep, or use for real work.

The weighted total

The two inverted axes are turned around before weighting, so every term rewards a higher number. Cheapness is 6 − cost. Safety is 6 − risk.

raw = 3×visual + 3×explain + 2×surprise + 1×kernel
    + 2×(6 − cost) + 2×(6 − risk) + 2×standalone

total = raw / 75 × 100          raw runs from 15 to 75

The weights say what this document is for. It is a set of pages that must show something and teach something, so visual and explain carry three each. Surprise, cheapness, safety and standalone value carry two each. Kernel exercise carries one, because stressing the library interests the builder and stays invisible to the reader.

The cost axis does not reproduce the tier counts exactly. The planning section splits the 121 into 64 Tier A, 31 Tier B and 26 Tier C. Scoring cost project by project gives 69 at 1 or 2, 29 at 3, and 23 at 4 or 5. The two counts were made independently and neither was fitted to the other. Where they disagree, trust the tier section for money and this axis for ordering.

Read the total as a build order, not as a quality score. It rewards cheap and safe work, so a hard project of real importance sits below an easy attractive one. Time

One project at a time, including running each page in Chrome and looking at it: 80 to 160 hours of agent work. With four to six subagents in parallel: 20 to 40 hours of wall clock, spread realistically over one or two weeks, because you must judge each page yourself. Parallel agents do not remove that step.

Which weights

About twenty projects need a real model, and each must fit in 4 GB beside the browser. Stay at roughly 500M parameters or below. A small sentence-embedding model covers every project in category 10. A sub-1B decoder covers category 5, and a four-bit build of the same model covers the comparisons in category 6. A small sparse model covers category 8. A detection backbone covers category 15.

No specific checkpoint has been tested from a localhost page on this laptop. Confirming that a Hugging Face resolve/ URL serves safetensors with headers a local page accepts is the cheapest thing to check before any Tier C work starts.

The recommendation

Do not build all 121. This document is worth more as a menu than as a backlog.

Build 10 to 15 first. Take one from each category that interests you, weighted toward Tier A. That costs 1.5 to 2.5 million tokens and two or three sessions. It also produces the number this whole section is guessing at, which is the true cost of one project on this hardware. Re-plan after that, with data instead of estimates.

If the full run still looks correct afterwards, run it in tier order, cheapest first: the 64 Tier A projects, then the 31 Tier B, then the 26 Tier C. Each batch tells you whether to continue, and the expensive tier becomes the last commitment instead of the first.

ClosingIf you build three of these, build these three

Start with the readback curve (category 17, project 3). It is half a day, it re-uses bench.html almost unchanged, and every other project depends on knowing the shape of that curve on your card.

Then the decoder layer with real weights (category 5, project 1). It is the headline. It is the one you show people. It also forces you to solve safetensors parsing, which unlocks every other project that needs real weights.

Then pick by taste. For the best picture, build the slime mould or the fluid. For the most useful tool, build the local notes search. For the biggest surprise, train the digit classifier in a browser tab with hand-written gradients.

Honest accounting of the 207

These 121 projects name 179 of the 207 kernels directly. That count was checked by extracting every kernel name from this file and comparing it against the Hub list. No invented name survived.

The 28 that go unnamed are not gaps in the plan. Six are duplicates that exist in both namespaces or as fusions of something already used: com.microsoft.Gelu, com.microsoft.LinearAttention, com.microsoft.CausalConvWithState, com.microsoft.BiasAdd, com.microsoft.BiasSoftmax and com.microsoft.EmbedLayerNormalization. Four more are normalisation variants that slot into any project in categories 2 and 5: ai.onnx.BatchNormalization, ai.onnx.InstanceNormalization, ai.onnx.GroupNormalization and ai.onnx.MeanVarianceNormalization. The remaining eighteen are plumbing and simple arithmetic — Flatten, Split, Squeeze, Unsqueeze, Neg, Not, Ceil, Reciprocal, Sum, Mean, the global pooling family, the two or equal comparisons, and the deprecated Scatter, Upsample and SplitToSequence. They support a project. They cannot anchor one.

What is still assumed, not verified

Three things in this document are reasoning rather than measurement, and each one is cheap to settle. First, that safetensors files fetch from a Hub resolve/ URL with headers that allow a localhost page — Transformers.js works this way, so it is likely, but it is not yet tested here. Second, that a model near 500M parameters fits comfortably in 4 GB alongside the browser. Third, that the com.microsoft kernels accept input layouts a hand-written page can produce. Every project above that depends on one of these says so in its ceiling line.
